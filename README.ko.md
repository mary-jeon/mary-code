# Mary

> **Rv.0 / plugin 0.5.0 · Experimental · Claude Code**
>
> [English](./README.md) (정본) · **한국어**
>
> 이 문서는 번역본입니다. 내용이 어긋나면 영문 README가 우선합니다.

**AI는 틀렸을 때도 설득력 있게 말합니다.**

Mary는 Claude Code용 환각 방지 하네스입니다. 모델을 바꾸지 않습니다. 일이 정의되고 실행되고 검증되고 기록되는 방식을 바꿔서, 그럴듯하지만 틀린 주장 하나가 그 뒤 모든 것의 토대가 되기 전에 잡습니다.

Mary는 절차이지 상주 프로그램이 아닙니다. **훅을 설치하지 않고, 백그라운드에서 아무것도 돌리지 않습니다.** 스스로 세션을 끊지 않고 다음 단계가 무언가를 되돌릴 수 없게 바꾸는 경우가 아니면 자리를 비운 사이에 묻지 않습니다.

## 0.5.0에 들어 있는 것

- **6단계 스킬**(`/mary`): 검증 가능한 주장과 판단을 분리하고, 주장은 관측 가능한 증거로 확인하고, 자기 산출물을 공격하고 고치고 다시 확인한 뒤에야 "완료"라고 말합니다.
- **환각이 실제로 태어나는 자리의 생산 규칙**: 출처 없는 숫자는 채워 넣지 않고 `미확인`으로 적는다. 입력값을 바꾸면 "확정" 전에 의존하는 값을 전부 다시 계산한다. 판정은 그 값을 만들었어야 할 파라미터가 아니라 실제 산출물에서 읽는다. 누락은 훑어봐서가 아니라 목록을 대조해서 찾는다.
- **읽기 전용 비평 에이전트**(`mary-critic`): 산출물을 명세에 대고 공격하되 회차마다 관점 축을 바꿔서 같은 층의 결함만 반복해서 찾는 일을 막습니다.
- **세션을 넘어 남는 실패 기록**(`FAILLOG.md`), 모델의 암산 대신 카운터를 다시 계산하는 **검산기**(`mary-stats.js`), 반복된 실패를 **사용자 승인으로만** 상시 규칙(`RULES.md`)에 올리는 승격 절차.
- **위임 규칙**: 한 번 "진행해"라고 하면 되돌릴 수 없는 행동이 다음 차례가 되기 전까지는 다시 묻지 않습니다. 되돌릴 수 있는 단계에서 승인을 구하는 것도, 되돌릴 수 없는 단계에서 승인을 건너뛰는 것과 같은 실패로 봅니다.

0.4.x에서 달라진 것: `PreToolUse` 승인 게이트와 관측 훅을 **더 이상 설치하지 않습니다.** 코드는 저장소에 선택 사항으로 남아 있습니다([선택 사항: 승인 게이트](#선택-사항-승인-게이트) 참조). 작성자 본인의 PC에서 5주 동안 승인 요청 727건 중 460건이 위험 없는 오탐이었고 전부 승인됐으며 결국 게이트가 꺼진 채로 끝났기 때문입니다. 꺼진 게이트는 없는 게이트보다 나쁩니다.

## 작동 방식

```text
0. 위험 점검     되돌릴 수 없는 행동 목록화; 검증 가능한 주장과 판단 분리
1. 명세          목표·완료 조건·제외 범위·각각의 확인 방법
2. 대안          근본적으로 다른 3안, 각각의 붕괴 조건
3. 안전 실행     되돌릴 수 있는 것부터; 되돌릴 수 없는 행동은 보류; 생산 규칙 적용
4. 검증          검증 → 반례(비평) → 수정 → 재검증, 영수증 남김
   4.5 실행      대상·범위 제시 → 승인 → 상태 재확인 → 실행 → 결과 관측
5. 적립          결과 기록; 두 작업에서 반복된 실패는 규칙 후보
```

Mary는 결론을 두 종류로 구분합니다.

- **검증 가능한 주장**은 실행·테스트·실측·diff·원문·권한 있는 검토자 확인 같은 관측 가능한 증거로 확인해야 합니다. 글로 쓴 "확인했다"는 증거가 아닙니다. 검증 영수증이 각 주장을 실제로 돌린 명령과 그 출력에 묶습니다.
- **판단 영역**(설계·전략·취향)은 검증된 것처럼 제시하지 않습니다. 추천안, 핵심 전제, 뒤집힐 조건, 남은 가치 판단의 소유자를 밝힙니다. 판단의 전제는 대개 사실이므로 추천 전에 조사합니다.

다른 모델의 비평은 별도의 관점이지 독립 검증이 아닙니다. 증거는 모델 자신의 주장 바깥에서 검사 가능해야 합니다.

정규 실패 키와 단계 매핑은 [`skills/mary/LAYERS.md`](./skills/mary/LAYERS.md)에 있습니다.

## 환각을 막는 규칙들

실패 기록이 "그럴듯하지만 틀린 산출물"이 어디서 나오는지 보여준 자리에 넣은 절차입니다. `SKILL.md` 3단계와 4-1에 있습니다.

| 규칙 | 막는 실패 |
|---|---|
| 출처 없는 값은 가정이며 `미확인`으로 적는다. 빈 칸이 지어낸 값보다 낫다. 가정 옆에는 무엇을 확인하면 확정되는지, 안전한 쪽으로 틀린 값인지 적는다 | 거짓 정밀도·창작: "볼밸브니까 ≈0.05"처럼 종류에서 유추한 계수가 나중에 비보수적으로 드러남 |
| 입력값을 바꾸면 산출물 전체에서 의존하는 곳을 전부 찾아 다시 계산한 뒤에야 "확정" | 국소 수정은 맞는데 그 값을 읽는 세 곳이 틀려짐 |
| 계산해 놓고 어떤 판정도 쓰지 않는 값은 그 자체가 결함 신호 | 산출물이 여유 치수를 계산하는데 옆 판정 칸은 글자 그대로 `pass` |
| 판정의 입력은 판정 대상과 독립: 만들어진 산출물에서 읽지, 그것을 만들었어야 할 파라미터에서 읽지 않는다 | 자기 입력을 읽는 검사는 항상 통과함 |
| 보고에 적는 숫자는 전부 산출물에서 읽은 값. 성분에서 손으로 계산하거나 요약에서 옮겨 적지 않는다. 마무리 보고 전 최종 숫자를 한 번 더 돌린다 | 산출물에 없는 값이 적힌 인계 문서 |
| 누락은 원본에서 필요한 항목을 전부 나열해 하나씩 대조해서 찾는다. 있는 것만 봐서는 없는 것을 못 찾는다 | 재계산·예외 검사·렌더 확인이 항목이 빠진 채로 전부 통과함 |
| 시간 압박은 산출물의 분량을 줄이지, 절차를 줄이지 않는다 | "한 시간밖에 없다"를 단계 생략 허가로 읽음 |
| 한 번 받은 위임은 세션 내내 유효. 보고는 턴을 끝낼 이유가 아니다. 멈추는 것은 되돌릴 수 없는 행동뿐 | 조기 종료, 그리고 반대 실패인 과잉 질문 — 사용자가 하네스를 끄게 만드는 것 |

## 언제 쓰나

설치 후 Claude Code에서 직접 호출:

```text
/mary
```

명시 호출은 작업 크기와 무관하게 전체 절차를 돌립니다.

다음 경우에는 자동 발동될 수 있습니다.

- 되돌릴 수 없거나 되돌리기 어려운 요청(삭제·덮어쓰기·외부 전송·배포·업무시스템 쓰기)
- 다단계 작업(초기 판단이 이후 결과에 영향)
- 사실 의존 작업(법령·수치·규격 같은 사실 판정이 결과를 좌우)

자동 발동은 모델 판단에 의존하므로 누락될 수 있습니다. 확실히 필요하면 `/mary`를 치세요.

단발 질문·설명·번역·조회에는 쓰지 않습니다. 모든 요청에 무거운 절차를 돌리면 하네스는 우회되기 쉬워지고 쓰기 어려워집니다.

### 작업 등급

| 등급 | 대상 | 처리 |
|---|---|---|
| **Standard** | 되돌릴 수 있는 저영향 작업 | Claude가 자율 진행하며 필요한 검증을 수행. 자동 발동 시 탐색·표현은 압축 가능하나 검증·승인은 압축 불가 |
| **Guarded** | 되돌릴 수 없는 행동; 법률·노무·세무·고비용; 되돌리기 어려운 설계 결정 | 검증 가능한 주장은 관측 증거 필수. 중요한 판단과 되돌릴 수 없는 행동은 사용자 확인 필수 |

Guarded는 탐색을 줄이지 않습니다. 결정을 확정하기 전에 요구되는 증거와 승인 수준을 높입니다.

### 자리를 비울 때

"진행해", "알아서 정해", "자리 비운다"라고 말해 두면 1·2단계 확인을 다시 묻지 않습니다. 고른 해석과 선택안을 기록하고 계속 갑니다. 무인 진행을 멈추는 것은 두 가지뿐입니다. 되돌릴 수 없는 행동은 항상 기다리고 검증 두 회차 연속으로 완료 조건이 하나도 닫히지 않으면 돌지 않고 보고합니다.

## 설치

최근 버전의 **Claude Code**(플러그인 지원)가 필요합니다. **Node.js**는 선택 사항인 검산기(`mary-stats.js`)와 선택 사항인 게이트에만 필요하고 스킬 자체에는 의존성이 없습니다.

### 마켓플레이스 설치 (권장)

Claude Code 안에서:

```text
/plugin marketplace add mary-jeon/mary-code
/plugin install mary@mary-code
```

그 다음 Claude Code를 재시작합니다. `mary@mary-code`로 설치되며 업데이트는 `/plugin` 메뉴로 받습니다.

### 수동 설치 — macOS / Linux

```bash
git clone https://github.com/mary-jeon/mary-code.git ~/.claude/skills/mary
claude plugin validate --strict ~/.claude/skills/mary
```

### 수동 설치 — Windows PowerShell

```powershell
git clone https://github.com/mary-jeon/mary-code.git "$HOME\.claude\skills\mary"
claude plugin validate --strict "$HOME\.claude\skills\mary"
```

`~/.claude/skills/` 아래에 `.claude-plugin/plugin.json`이 있는 폴더는 다음 세션에 스킬 디렉터리 플러그인으로 로드됩니다. `mary@skills-dir`로 보이고 스킬은 `/mary:mary`(모호하지 않으면 `/mary`)로 호출합니다.

Git 대신 **Code → Download ZIP**을 쓰면 저장소 전체를 풀고 폴더 이름을 `mary`로 바꿔 `~/.claude/skills/mary/.claude-plugin/plugin.json`이 존재하게 하세요.

### 업데이트

```bash
git -C ~/.claude/skills/mary pull --ff-only        # macOS / Linux
git -C "$HOME\.claude\skills\mary" pull --ff-only   # Windows PowerShell
```

그 다음 Claude Code를 재시작하거나 `/reload-plugins`를 실행합니다.

## 상태·기록 파일

Mary는 런타임 상태를 저장소 밖 `~/.claude/mary/`에 둡니다. 파일은 필요할 때 생성되고 이 저장소에 올라가지 않습니다.

| 파일 | 역할 |
|---|---|
| `RULES.md` | 승인된 상시 규칙과 확인된 사실. 하나 |
| `FAILLOG.md` | 관측된 실패, 기각된 반례, 카운터, task ID, 승격 상태. 하나 |
| `_work-<슬러그>.md` | 작업 흐름당 하나의 진행 기록. 완료된 것만 삭제. 멈춘 기록이 남아 있어야 다음 세션의 "이어서"가 실제로 됩니다 |

## Mary가 실패에서 배우는 방식

1. 실패·증거·정규 키·scope·고정 `task_id`를 `FAILLOG.md`에 기록합니다.
2. 한 작업은 세션이 갈라져도 종료 상태가 바뀌어도 정확히 한 번만 셉니다.
3. 같은 실패 키가 서로 다른 두 task ID에서 재현되면 규칙 후보가 됩니다.
4. 제안 규칙 한 줄과 근거 사건 2건을 보여줍니다.
5. 사용자가 승인한 규칙만 `RULES.md`에 들어갑니다.
6. 잘못된 상시 규칙은 나중에 수정·삭제될 수 있습니다.

기각된 반례는 따로 저장되며 승격에 절대 반영되지 않습니다. 승격 범위는 실제 관측된 scope로 한정됩니다.

위 표의 규칙들은 작성자 본인의 기록에서 승격까지 갔고 절차 자체에 실을 만큼 일반적이었습니다.

> `FAILLOG.md`는 Mary가 발동한 동안 관측된 실패의 기록입니다. 모델이 낸 모든 실패의 완전한 추정치가 아닙니다.

## 선택 사항: 승인 게이트

저장소에는 인식된 되돌릴 수 없는 셸 명령(삭제, `git push`, 파괴적 git, 원격 동기화, 패키지 배포, 파괴적 SQL, 자기 설정 편집) 앞에서 허가를 묻는 `PreToolUse` 훅, 그리고 각 승인을 실제 결과에 묶는 관측 훅이 아직 들어 있습니다. **플러그인은 이것을 설치하지 않습니다.** 원하면 [`docs/gate.md`](docs/gate.md)를 따라 직접 등록하세요. 그 문서에는 2026-09 검토에서 재현됐지만 아직 고치지 않은 우회 경로 목록도 있고, 위협 모델은 [`docs/threat-model.md`](docs/threat-model.md)에 있습니다.

코드 없이 되는 더 가벼운 방법은 Claude Code 자체의 권한 규칙입니다. 예를 들어 설정에 `"permissions": { "ask": ["Bash(git push:*)"] }`를 두면 그 명령 모양에만 묻습니다. 문자열 대조라 게이트가 파싱으로 막는 래퍼·따옴표 우회는 못 막지만 개인용 체크포인트로는 충분한 경우가 많습니다.

## 설계 원칙

- **생각은 자유롭게, 확정은 엄격하게.** 탐색은 열어 두되 파급이 있는 결론에는 증거를 요구한다.
- **되돌릴 수 있는 작업은 자율로.** 모호함·고영향·되돌릴 수 없는 결정만 올린다.
- **사실과 판단을 분리한다.** 사실은 검증하고 판단은 전제와 뒤집힐 조건을 드러낸다.
- **모델 비평은 관점이지 증명이 아니다.** 독립 증거는 실행·테스트·실측·원문·권한 있는 검토자에서 온다.
- **효과를 관측한 뒤에 성공을 보고한다.** 없는 결과는 `unknown`이지 자동으로 실패가 아니다.
- **세션은 소모품, 파일은 자산.** 작업 상태와 실패 이력은 세션 경계를 넘어 살아남는다.
- **나쁜 규칙은 내려올 수 있어야 한다.** 승격된 규칙은 영구 진리가 아니다.
- **꺼진 하네스는 아무것도 지키지 못한다.** Mary는 시키지 않은 것을 돌리지 않고 다음 단계가 되돌릴 수 없는 경우가 아니면 묻지 않는다.

## 현재 한계

- 자동 발동은 누락되거나 불필요하게 적용될 수 있습니다.
- Claude가 명세 초안을 먼저 쓰는 구조는 사용자를 모델의 초기 프레임에 정박시킬 수 있습니다.
- 절차를 기계적으로 강제하는 것은 없습니다. Mary는 지시와 기록이며 스킬을 무시하는 모델을 막지는 못합니다. 선택 사항인 게이트는 기계적 검사가 비용을 치를 만한 단 한 부류, 되돌릴 수 없는 셸 명령을 위해 남겨 두었습니다.
- 별도 LLM 검토자는 생성자와 편향을 공유할 수 있습니다. 관측 가능한 증거의 대체물이 아닙니다.
- 결정 재추적 엔진(무효화된 전제에 의존한 결정만 다시 열기)은 명세만 있고 미구현입니다.
